# httpee — архитектура пакета

Пакет `httpee` — тонкая обёртка над httpx: функции-глаголы и функции-модификаторы,
спроектированные под eelang-пайплайны (`..f(x)` = `f(x, значение)`). Здесь — границы,
семантика и решения; «что и зачем» — в `httpee-client`.

## Компоненты

- **`httpee` (один модуль)** — весь публичный API: глаголы `GET`, `POST`, `PUT`, `PATCH`,
  `DELETE`, `HEAD`, `OPTIONS` и `send`; модификаторы `headers`, `query`, `timeout`, `cookies`,
  `auth`, `json`, `method`, `url`; класс `Response`.
- **`_Request` (внутренний)** — накапливаемое состояние запроса: `method`, `url`, тело
  (`body` / `json_body`), `headers`, `params`, `timeout`, `cookies`, `auth`. Пользователю
  не виден; в пайплайне его роль играет любое значение — тело (dict/str/bytes/None) или уже
  собранный `_Request`.
- **Выполнение** — глагол создаёт новый `httpx.Client`, собирает `httpx.Request` из `_Request`,
  отправляет и возвращает `Response`.

## Семантика

- **Модификатор** `..f: x` = `f(x, значение)`: на значении-теле оборачивает его в `_Request`
  и применяет параметр; на `_Request` — дополняет. Модификаторы повторяемы и в любом порядке
  перед глаголом. Применение после глагола (на `Response`) — `TypeError` с внятным сообщением.
- **Глагол** `..GET: url` = `GET(url, значение)`: выполняет запрос. Тело: dict → form-encoded
  (`data=`), str → текст, bytes → сырые байты; `..json: {…}` → `json=` (побеждает над телом).
- **`Response`** — подкласс `httpx.Response` со свойством `status` (→ `status_code`); глагол
  оборачивает ответ httpx в него, чтобы class-паттерн `Response(status=200)` работал
  (isinstance + getattr). Остальное — родное: `.json()`, `.text`, `.headers`,
  `.raise_for_status()`.
- **`..send()`** = `send(значение)`: выполняет запрос с заранее заданными `..method:`
  (по умолчанию GET) и `..url:` (обязателен — без него `TypeError` с внятным сообщением).
  Глагол в конце (`..GET:`) переопределяет ранее заданный метод и выполняет сразу.
- **4xx/5xx не кидаются** — `raise_for_status` не вызывается; статус проверяет
  `..assert:`/`..match:` (провал ассерта — `MatchError` из eelang, не из пакета).
  Сетевые ошибки и таймауты — исключения httpx как есть.

## Решения и инварианты

- **Никакого глобального состояния.** Каждый запрос — новый `httpx.Client` (как модульный API
  requests); переиспользуемые сессии — вне v1.
- **Только sync.** `httpx.Client`, никаких потоков и event loop'ов; работает под
  monkey-patched gevent (блокирующие сокеты).
- **Пакет — обычный Python, eelang не импортируется.** Пайплайновость даёт язык на месте
  вызова; сам модуль от eelang не зависит (зависимость одна — httpx).
- **Имена — часть контракта:** глаголы-методы ЗАГЛАВНЫМИ (совпадают с HTTP-методами),
  `send` и модификаторы — строчные английские слова. Изменение имён ломает пайплайны.
- **Таймаут по умолчанию** — httpx'овский (5 c); `..timeout:` переопределяет на запрос.
- **Один модуль.** Пакет укладывается в `httpee/__init__.py`; дробить нечего.

## Границы

- Зависимость только на httpx; eelang нужен лишь для запуска `.eel`-скриптов.
- Не поднимает ошибок на 4xx/5xx — это контракт для `..assert`/`..match`.
- Вне v1: сессии (`..using:`), async, retry, streaming, загрузка файлов — см. `httpee-client`.
